## V1.1 engineering hardening additions

- Real evaluation harness: `evals/run_eval.py` now runs a deterministic, rule-based classifier (`services/api/app/classify.py`, also exposed as `POST /cases/classify`) against `evals/datasets/cases.jsonl` and asserts the predicted type/risk against the expected labels, instead of only checking that the dataset rows have the right fields. A classifier regression now fails the build.
- `services/api/tests/`: a pytest suite covering i18n localization, the translation demo-table fallback, the classifier, the new API key gate, and an end-to-end check that `POST /cases/{id}/analyze` is idempotent.
- CI (`.github/workflows/ci.yml`) now runs that pytest suite on every push/PR and adds a `docker-compose-smoke-test` job that boots the real stack with `docker compose up --wait` and curls it, closing the previous gap where the Docker Compose path was never exercised by CI.
- A pilot-stage, off-by-default shared-secret API key gate (`services/api/app/security.py`, `REQUIRE_API_KEY` / `API_KEY`) that can be switched on per-environment without a code change. This is an interim network-boundary control, not a replacement for enterprise SSO/OIDC (still listed below).
- `infra/kubernetes/` manifests gained liveness/readiness probes, resource requests/limits, a `HorizontalPodAutoscaler`, an example `Secret` documenting the required keys, and an example `Ingress`.
- `infra/terraform/` is now a working (if intentionally minimal and AWS-specific) starter — VPC, encrypted RDS PostgreSQL, encrypted ElastiCache Redis, encrypted/KMS-backed S3 — validated with `terraform validate`, replacing what used to be a plain text checklist.
- Fixed a documentation bug: the Docker quick-start section pointed at port 8000, while `docker-compose.yml` maps the API container to host port 8001.

## V1.2 real multi-agent reasoning upgrade

Previously, `POST /cases/{id}/analyze` was a script: it branched on one hardcoded `case_id`, inserted fixed English sentences and fixed millisecond durations, and picked evidence by hand. The 20-agent directory in `agents.py` was display-only -- none of its listed tools were ever called. This release replaces that script with a real pipeline:

- `services/api/app/retrieval.py`: a dependency-free TF-IDF cosine-similarity search engine over `KnowledgeDocument`, indexing both the English and Chinese text of every document so a query in either language retrieves evidence authored in the other, without a translation call. Every ranking is reproducible from its similarity score.
- `services/api/app/workflow.py` (rewritten): `Case.type` now selects which specialist agents from the `agents.py` directory actually run (`SPECIALISTS_BY_CASE_TYPE`) -- an HSE case engages the HSE/Compliance/Workforce agents, a contract/technical case engages Contract/Engineering/Interface, etc. Each engaged agent runs a real retrieval query grounded in the case's own text and only cites evidence it actually found; when similarity is too low to support a conclusion it says so explicitly instead of asserting one -- for any case, not just the one that used to be hardcoded.
- Evidence confidence, and the Verification agent's citation/evidence/consistency scores, are computed from the evidence and findings this run actually produced, not fixed numbers.
- Agent-run durations are now the real measured wall-clock time of the search + synthesis, not canned constants.
- When a real OpenAI-compatible model is configured (`llm_mode` != `mock` and `OPENAI_COMPAT_API_KEY` set), each specialist's finding is generated by that model, grounded in the same retrieved evidence, and translated through the same model. The default, network-free mode builds the same finding directly in both languages from the already-bilingual knowledge documents, so the offline/CI path stays fully deterministic without depending on a fixed phrase table for text that was never known in advance -- `translations.py` was pruned of the now-dead per-case strings this replaces.
- New tests: `tests/test_retrieval.py` (the search engine itself), `tests/test_workflow.py` (different case types provably engage different agents and produce evidence/scores grounded in the real knowledge base), `tests/test_workflow_llm_mode.py` (the real-model code path is actually exercised, not just the offline fallback).

# GlobalInfra AI V1.1 领域架构

## 1. 产品模型

GlobalInfra AI 是一个**具备生命周期感知能力的基础设施智能与可信执行平台**。聊天只是可选项；真正的记录系统是项目工单及其证据、决策、行动、审批与核验历史。

该模型有两个轴：

```text
生命周期: 投标 → 规划 → 设计 → 采购 → 施工 → 调试 → 移交 → 运维
智能领域: 项目 → 工程 → 交付 → 商务 → 保证 → 资源 → 知识 → 资产
```

八大智能领域包含 24 个专业学科。它们是同一个互联项目模型的不同视图，而不是彼此独立的应用。

核心领域链条：

```text
组织 → 项目 → 生命周期阶段 → 领域 → 事件 → 工单 → 证据 → 决策 → 行动 → 核验
```

## 2. 全局拓扑

```text
全局控制面（Global Control Plane）
  身份 / 租户 / 智能体目录 / 技能注册表 / 模型注册表 / 国家包注册表 / 策略
          │
          ├── 亚太数据面（APAC Data Plane）
          ├── 中东非数据面（MEA Data Plane）
          └── 欧洲数据面（EU Data Plane）
                   │
               项目边缘（Project Edge）
        离线缓存 / 安全同步 / 本地工具
```

V1.0 以单一可部署的区域化技术栈运行。边界已预先建模，后续可以按区域拆分服务。

## 3. 基础设施数字主线

```text
资产 → 图纸 → 规范 → 工作包 → 施工方案 → 检验 → 不符合项（NCR）
      → 技术决策 → 合同影响 → 进度 / 成本影响
      → 纠正措施 → 核验 → 经验教训
```

关系会在跨领域场景下保留因果、责任、时间、成本、风险与核验上下文。

## 4. 可信执行模型

```text
现场事件
  ↓
工单智能
  ↓
知识检索 + 专家智能体
  ↓
行动计划
  ↓
人工治理
  ↓
执行
  ↓
独立核验
  ↓
证据记录
```

当审批或证据缺失时，重要的对外行动必须默认失败关闭（fail closed）。

## 5. 智能体模型

智能体不是不受约束的自主进程。每个智能体都必须具备：

- 明确的角色；
- 输入/输出数据结构（schema）；
- 已批准的工具；
- 证据策略；
- 风险等级；
- 执行预算；
- 审批策略。

工单路由器（Case Router）会对每个事件进行分类，并组建最小合适的专家团队。一个复杂的不符合项（NCR）可能会激活质量、工程、合同与计划智能体，而无需运行全部已注册的智能体。

## 6. 知识网络

V1.0 使用关系型的模拟知识记录。生产环境的演进方向：

- 对象存储：源文档
- PostgreSQL：权威元数据与领域状态
- pgvector / OpenSearch：语义 + 词法检索投影
- 图数据库：主张/证据/实体关系

索引是可重建的投影；源文档与权威元数据才是真正的记录系统。

## 7. 国家包（Country Packs）

国家包用于隔离：

- 语言 / 区域设置 / 从右到左书写支持；
- 术语；
- 本地工作流策略；
- 数据驻留元数据；
- 已批准的监管信息来源；
- 国家特定的模板。

国家包是配置 + 经过整理的知识，而不是让 AI 凭空编造法律结论的许可。

本次升级中，Web 前端与 API 已经落地了一套贯穿全链路的语言切换机制（浏览器语言自动识别 + Cookie 记忆 + 后端双语数据 + 翻译模型集成点），作为国家包中“语言/区域设置”能力的具体实现基础；`packages/country-packs/*/glossary.json` 中的术语对照结构可以直接复用到翻译模型的术语锁定环节。

## 8. 领域包（Domain Packs）

领域包隔离交通垂直行业语义：铁路、公路、桥梁、隧道、港口与机场。

## 9. 模型网关

`LLM_MODE=mock` 是默认模式。生产环境必须按照敏感度、延迟、成本、能力、司法辖区与数据策略进行路由，并且在不允许跨境处理数据时，必须支持本地/区域化的模型路由。翻译模型集成点（`services/api/app/llm.py` 中的 `translate()`）复用同一套模型网关抽象：有真实模型配置时调用真实模型，否则回退到确定性的离线短语表，保证演示环境无需联网也能产出双语内容。

## 10. 部署演进路径

- V1 竞赛阶段：Docker Compose，单一区域。
- 试点阶段：托管 PostgreSQL、Redis、对象存储、专用网络、SSO。
- 企业阶段：Kubernetes、区域化数据面、集中式控制面、策略即代码（policy-as-code）、KMS/HSM、SIEM。
- 边缘阶段：离线优先 PWA、加密本地缓存、存储转发式同步。
